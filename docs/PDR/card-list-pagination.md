# カード一覧の表示方式

## このPDRで決めること

カード一覧において、一定件数ずつ取得したカードの表示方式として、ページネーションと無限スクロールのどちらを採用するか決める。

## 背景

カード数が増加した場合、すべてのカードを一度に取得・描画すると、通信量やブラウザの描画負荷が増加する。そのため、カードを一定件数ずつ取得し、カード数が増加しても快適に一覧を閲覧できるようにしたい。

### その他背景

- カード一覧では、作成日の新しい順 / 古い順への並び替えと、すべて / チェックあり / チェックなしの絞り込み機能を実装する予定
- 本アプリでは、カードの手動並び替え機能は実装しない
- カードを使って覚えることは学習画面で行い、カード一覧はカードの確認・編集・削除を行う管理画面としての役割を持つ

## 案の比較

### 比較軸

- UI/UX
- 実装のシンプルさ
- フロントエンドで保持するデータ量

### 案1：ページネーション

カードを一定件数ごとのページに分け、「次へ」「前へ」やページ番号によって表示するカードを切り替える。

**メリット**

- 一度に表示・保持するカード数を一定件数に抑えられる
- 任意のページへ直接移動できる
- 一覧上の現在位置をページ番号として把握しやすい
- 以前閲覧していた位置へ戻りやすい
- ページごとにデータを取得して置き換えるため、フロントエンドの状態管理がシンプルになる
- 現在のページをURLで管理でき、リロード時も同じページを表示しやすい

**デメリット**

- 一定件数を確認するたびにページを切り替える操作が必要になる
- ページ番号や「次へ」などの操作UIが必要になる
  - 特にスマートフォンでは、ページ切り替えのためのUIが表示領域を使用する
- 絞り込みによってページ構成が変わるため、ページ番号自体に大きな意味を持たせにくい

### 案2：無限スクロール

最初に一定件数のカードを取得し、一覧の末尾付近までスクロールした際に次の一定件数を取得して、現在の一覧へ追加する。

**メリット**

- ページを切り替えず、スクロール操作を続けるだけで一覧を確認できる
- ページ番号などの操作UIを必要としない
- スマートフォンでも通常のスクロール操作で一覧を連続して確認できる
- 並び替え・絞り込み後も、条件を指定した後はスクロール操作だけで一覧を確認できる

**デメリット**

- 読み込みを続けると、フロントエンドで保持するカード数が増加する
- 一覧上の特定位置へ直接移動しにくい
- 大量のカードを読み込んだ状態では、一覧内の現在位置を把握しにくい
- 一度離れた位置へ戻る操作がページネーションと比較して行いにくい
- リロード時に、取得済みのカードやスクロール位置をどこまで復元するかを考慮する必要がある

## 採用する案

ページネーションを採用する。カードを一定件数ずつAPIから取得し、ページを切り替えた際に対象ページのカードを取得して、現在表示しているカード一覧を置き換える。

## 理由

無限スクロールはページを切り替えることなく連続して閲覧できるメリットがある一方、読み込みを続けるほどフロントエンドで保持するカード数が増加する。また、追加読み込みや取得済みデータの管理など、ページネーションと比較して状態管理が複雑になる。
ページネーションではページを切り替える操作やUIが必要になるものの、一度に表示・保持するカード数を一定にできる。また、ページごとに取得したカードで一覧を置き換えるため、カードの追加・編集・削除が発生した場合も現在のページを再取得することで表示内容を更新しやすい。
以上から、連続して閲覧する際の操作の少なさよりも、管理画面としての分かりやすさと実装・状態管理のシンプルさを重視し、ページネーションを採用する。
