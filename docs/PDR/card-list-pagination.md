# カード一覧の表示方式

## このPDRで決めること

カード一覧において、一定件数ずつ取得したカードの表示方式として、ページネーションと無限スクロールのどちらを採用するか決める。

## 背景

カード数が増加した場合、すべてのカードを一度に取得・描画すると、通信量やブラウザの描画負荷が増加する。そのため、カードを一定件数ずつ取得し、カード数が増加しても快適に一覧を閲覧できるようにしたい。

### その他背景

- カード一覧では、作成日の新しい順 / 古い順への並び替えと、すべて / チェックあり / チェックなしの絞り込み機能を提供する予定
- 本アプリでは、カードの手動並び替え機能はなく、並び順に意味を持たせることはできない

## 案の比較

### 比較軸

- UI/UX

### 案1：ページネーション

カードを一定件数ごとのページに分け、「次へ」「前へ」やページ番号によって表示するカードを切り替える。

**メリット**

- 任意のページへ直接移動できる
- 一覧上の現在位置をページ番号として把握しやすい
- 以前閲覧していた位置へ戻りやすい

**デメリット**

- 一定件数を確認するたびにページを切り替える操作が必要になる
- ページ番号や「次へ」などの操作UIが必要になる
  - 特にスマートフォンでは、ページ切り替えのためのUIが表示領域を使用する
- 本アプリでは、絞り込みによってページ構成が変わるため、ページ番号自体に大きな意味を持たせにくい

### 案2：無限スクロール

最初に一定件数のカードを取得し、一覧の末尾付近までスクロールした際に次の一定件数を取得して、現在の一覧へ追加する。

**メリット**

- ページを切り替えず、スクロール操作を続けるだけで一覧を確認できる
- ページ番号などの操作UIを必要としない
- スマートフォンでも通常のスクロール操作で一覧を連続して確認できる
- 並び替え・絞り込み後も、条件を指定した後はスクロール操作だけで一覧を確認できる

**デメリット**

- 一覧上の特定位置へ直接移動しにくい
- 大量のカードを読み込んだ状態では、一覧内の現在位置を把握しにくい
- 一度離れた位置へ戻る操作がページネーションと比較して行いにくい

## 採用する案

無限スクロールを採用する。カードは一定件数ずつAPIから取得し、一覧の末尾付近までスクロールした際に次のデータを取得して、現在表示しているカード一覧へ追加する。

## 理由

本アプリでは、カード一覧を細かく管理することよりも、カードを使って覚える作業を重視している。そのため、カード一覧上の位置や並び順自体には大きな意味を持たせていない。
ページネーションのメリットである任意のページへ直接移動する操作を必要とする場面は少なく、一覧上の位置から目的のカードを探すよりも、作成日の新しい順 / 古い順への並び替えや、チェックあり / チェックなしによる絞り込みによって対象を限定し、その結果を確認する使い方を想定している。
以上から、カードを細かく管理するための操作性よりも、並び替え・絞り込み後のカードを少ない操作で連続して確認できることを重視し、無限スクロールを採用する。
