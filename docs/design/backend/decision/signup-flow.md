# サインアップフローについて検討

## ゴール

サインアップ時におけるメールアドレスの本人確認フローを決める。

## 比較軸

- セキュリティ
- 保守性

## 比較した案

### 案A: メールの確認リンクを踏んで本人確認する

概要:

- サインアップ時に確認リンク付きメールを送信し、リンクを踏んだら有効化する

メリット:

- 実装パターンが一般的で情報が多い

デメリット:

- URLにトークンが含まれるため、漏洩リスクを考慮する必要がある

### 案B: メールで受け取ったOTPコードを入力して本人確認する

概要:

- サインアップ時にワンタイムコードを送信し、画面入力で確認する

メリット:

- トークンをURLに載せない設計にできる

デメリット:

- ユーザーの入力負荷が増える
- ワンタイムコード再送・総当たり対策などの実装が増える

## 採用案

採用する案:

- 案A: メールの確認リンクを踏んで本人確認する

採用理由:

- ユーザー操作が直感的で、一般的なサインアップフローとして受け入れられやすい
- 実装パターンが一般的で、参考にできる情報が多い
- ワンタイムコード入力方式と比べて、入力試行回数の制御や総当たり対策の実装がシンプル
