# 設計判断メモ

## フロントエンドのコンポーネント構成について

page、container、uiの三層の構造にした。containerはロジックの責務を持っており、storeの状態管理や関数を利用します。
containerからuiへ、storeのデータはpropsで渡すようにする。また、関数についてもuiからstoreを利用するのではなく、emitでcontainerへ伝えるようにします。
uiは画面に表示される検索ボックスや一覧リストなど、uiの責務を持っています。
pageはルーティングの入り口という役割を持っています。pageはなるべく薄くなるようにcontainerだけをもつようにします。

この構成にした理由は、3つあります。

- pageファイルが肥大するの避けるため。
- 状態管理や更新関数などのロジックを書く場所を明確にするため。
- uiコンポーネントを再利用をしやすくするため。
